Choose the right installation guide

Use the Windows installer and portable ZIP guide for the desktop application, or the Android APK guide for the phone app. Both are free pre-releases. The instructions below concern Windows unless explicitly stated otherwise.

How to verify a VideoView download

In PowerShell, open the folder holding your download and run Get-FileHash with its exact filename:

Get-FileHash .\VideoView-Setup.exe -Algorithm SHA256

For the ZIP or APK, substitute that file's name. Compare all 64 hexadecimal characters with the official checksum manifest; letter case does not matter. A mismatch means the files differ: do not run it, download again from the official release and report a persistent mismatch.

A matching hash confirms the file matches the published checksum. It is not proof of safety, a verified publisher certificate, or completed software testing. The Windows installer is unsigned and Android signing has not been independently checked.

Media formats and playback limits

The Windows file dialog accepts MP4, MKV, AVI, MOV, WMV, WebM, MPEG/MPG, TS/MTS, FLV, MP3, WAV, AAC, FLAC, M4A, OGG and Opus, plus other engine-supported local media. A file extension identifies a container or format; it does not guarantee support for every codec, profile or damaged file.

The bundled LGPL VLC package supplies the playback engine; its optional GPL plugin package is not included. The release QA describes narrower Linux diagnostics for H.264/AAC MP4, MKV, VP9/Opus WebM, WAV, FLAC and a short 4K H.264 sample. These checks do not certify Windows decoding, audible audio, sustained 4K performance or smooth 4× playback.

Local files and selected UNC paths are documented. URL streaming, DRM playback, casting, disc-menu workflows and timeline frame previews are outside the current scope. Android format support needs a separate device test matrix.

Subtitles and playback controls

The Windows app offers external SRT, VTT, ASS and SSA files. Use Ctrl + L to load subtitles, then select the intended track. Start with delay at zero; adjust timing only after confirming the subtitle file matches the video.

Font, size, color, placement, encoding and delay preferences are documented. Styled or bitmap subtitles can override font preferences. Manually loaded subtitle paths and track choices are per-session. Linux tests established track discovery, not correct glyph rendering, styling or synchronization on Windows.

Use Playback → Normal speed to reset speed, or right-click the speed selector. Mini mode and narrow windows can hide the full sound/speed controls; enlarge the window or exit mini mode to reach them.

Troubleshooting common Windows issues

The application will not start or a library is missing

Confirm that you downloaded the x64 package and extracted every file. Keep the bundled runtime and libvlc folder beside the application. Re-download if the checksum differs. Do not mix x86 or ARM64 native libraries into this package. Review the requirements and report the exact error.

I see a black picture

The source README suggests Automatic renderer, disabling hardware decoding in the app's preferences, and reopening the file. Check the same file in another player to distinguish a media problem from this pre-release. Native Windows GPU output has not been verified.

There is no sound

Check Windows and app mute/volume, select an audio track if the file contains several, and check Audio → Output device. Try System default. Record your output device and file format if the problem continues.

Subtitles are missing or have the wrong characters

Select the loaded subtitle track, reset the delay, check the file's encoding and confirm it belongs to the video. Auto-matching expects related media and subtitle filenames. Test a simple SRT file before diagnosing more complex ASS styling.

Where are settings stored?

Settings, history and logs use %LOCALAPPDATA%\VideoView, including with the portable edition. The source documents recovery copies for corrupt JSON. Back up this folder before troubleshooting stored data, and do not delete personal media.

Does VideoView relate to Android's VideoView programming component?

This site distributes the VideoView media-player project maintained by premangshumal-cyber. Android also has a programming component named android.widget.VideoView; its API documentation is a separate subject.

Official project support and feedback

Website and release support is handled through the VideoView GitHub issue tracker. This is community project support; no response time or commercial support contract is promised.

Include the edition and version, OS version, download filename, checksum result, steps to reproduce, expected result and exact error. For playback, add the file container and codec if known. For Android, include the device model and Android version. Check for an existing report first.

GitHub issues are public. Remove account details and personal file paths from logs and screenshots; do not upload private media. See the privacy and license information and release testing status.
